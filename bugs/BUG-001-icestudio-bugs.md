# BUG-005: IceStudio Installation & FPGA Deployment Issues

## Basic Information
| Field | Details |
|-------|---------|
| **Bug ID** | BUG-001 |
| **Status** | Partially Resolved (Workaround exists) |
| **Severity** | High |
## Description
Two separate but related issues were encountered when trying to use IceStudio with the Colorlight 5A-75B v8.2 board:

1.  **IceStudio Installation Error:** A "Package not installed" error appears when trying to verify or build a basic example (like "One LED") even though the toolchain appears correctly installed.
2.  **Cannot Deploy Bitstream:** IceStudio cannot directly deploy the generated `.bit` file to the FPGA when using a USB Blaster.

## Issue 1: IceStudio "Package not installed" Error

### Steps to Reproduce
1.  Launch IceStudio.
2.  Go to `File` -> `Examples` -> `Basic` -> `One led`.
3.  Click the `Verify` or `Build` button.

### Expected Behavior
The design should verify/build without errors.

### Actual Behavior
An error message appears: "Package not installed".

### Root Cause (Hypothesis)
This appears to be an issue with newer versions of `apio` (the underlying toolchain manager) breaking the expected package structure for a fresh IceStudio install.

### Working Solution
The following workaround was found in [IceStudio Issue #906](https://github.com/FPGAwars/icestudio/issues/906#issuecomment-4311926681) (credit to user `AmirLoveTeto`):

1.  **Locate the IceStudio path** (on Ubuntu: `/home/$USER/.icestudio`).
2.  **Activate the Python virtual environment** used by IceStudio:
    ```bash
    source venv/bin/activate
    ```

3.  **Install a specific version of Apio** (v0.9.5):
    ```bash
    pip install apio==0.9.5
    ```
4.  **Create required directories** inside the IceStudio path (e.g., `~/.icestudio`):
    ```bash
    mkdir -p apio/packages
    ```
5.  **Download and extract packages** into `apio/packages/`:
    -   `tools-oss-cad-suite` v0.0.9 → rename extracted folder to `tools-oss-cad-suite`
    -   `apio-examples` v0.0.36 → rename extracted folder to `examples`
6.  **Create `profile.json`** inside the `apio/` directory with the following content:
    ```json
    {
        "config": {
            "exe": "default",
            "verbose": 0
        },
        "packages": {
            "examples": {
                "version": "0.0.36"
            },
            "oss-cad-suite": {
                "version": "0.0.9"
            }
        },
        "settings": {}
    }
    ```
    The final structure should be:
    ```
    .icestudio
    ├── venv
    └── apio
        ├── packages
        │   ├── examples
        │   └── tools-oss-cad-suite
        └── profile.json
    ```



## Issue 2: Cannot Deploy .bit File from IceStudio via USB Blaster

### The Problem
IceStudio does not have native support for deploying a generated bitstream directly to the Colorlight 5A-75B v8.2 using a USB Blaster.

### Workaround
Use `openFPGALoader` from the command line to flash the `.bit` file generated by IceStudio.

1.  **Install openFPGALoader** (if not already installed):
    ```bash
    # On Ubuntu/Debian
    sudo apt install openfpgaloader
    ```
2.  **Connect the USB Blaster** and ensure it is detected.
3.  **Run the deployment command**:
    ```bash
    openFPGALoader -b usb_blaster your_design.bit
    ```

## Additional Notes
-   The IceStudio installation issue seems to affect fresh installs on newer systems. The fix above forces the use of a known-working `apio` version and manually provides the required packages.
-   For the deployment issue, integrating `openFPGALoader` into the IceStudio workflow is a manual step but works reliably. You could also create a small script to automate this.
